Install it in CI

The action runs in your workflow, comments the score on the pull request and fails the check when the score drops.

# .github/workflows/gatecheck.yml
name: gatecheck
on: [pull_request]
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: Edmarkavs/gatecheck@main
        with:
          fail-under: 70

Questions

Does it run my code?

No. Gatecheck only reads files: the tree, the context file, the SKILL.md headers. No npm install, no tests, no model calls. That's why it takes seconds and why you can safely point it at a private repo.

Which agents does this apply to?

Any agent that reads a repo — Claude Code, Codex, Cursor, Copilot Workspace, Pi, OpenCode. The context-file convention differs slightly, but the failure modes (dead paths, stale stack, oversized context) are identical.

Why does a high-star repo score F?

Because stars measure attention, not setup. A collection of 800 skills with no context file, no CI and no lockfile gives an agent nothing to work from — it will guess your test command and get it wrong.

Is the score gameable?

Partly, and that's fine. The truth signal can be farmed by deleting every claim from your AGENTS.md — which is also the honest fix for a file full of lies. You get points for being small and correct, not for sounding thorough.
